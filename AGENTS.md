# Global Rules

# Keep It Small and Smart

- Build the smallest slice that works.
- Pick the simplest design that fits; justify every extra part in writing.

# Language Applies To Everything

- Answer in the language the person used. Never switch languages.
- The language rules bind every word: replies, code comments, commit
  messages, docs.

# Local Overrides

- If `AGENTS.local.md` exists here, read and follow it; it extends these rules.

# Use Your Skills

- Start every task with the `skill-router` skill. A matching skill outranks
  your defaults. Name what you loaded.

# Spec-Driven Development

- Write the spec before any code.
- Specs state what and why, never how.
- Mark every open question; never guess.
- Regenerate plans from specs when requirements change.

# Technical Writing

- Keep sentences short; about 20 words maximum.
- Use active voice and direct commands.
- Write one instruction per sentence.

# Write Simply

- Use common words; explain jargon on first use.
- Give concrete examples.

# Token-Efficient Commands

- If `rtk` exists, prefix commands: `rtk git status`. On odd output run plain.
